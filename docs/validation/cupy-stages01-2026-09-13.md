# Actual CUDA Stage-0/1 execution — 2026-09-13

RES083 connects the schema backend to real particle-stage work while retaining NumPy
public arrays. Conservative overlap windows, small kinematic vectors and bin-edge
construction remain on the CPU. Trajectory/intensity evaluation, source histograms,
and nearest/CIC deposition execute with CuPy when selected. Retargeting remains NumPy.

## Device and numerical checks

`tests/test_xigma_cupy_stages01.py` observes CuPy arrays inside LaserField evaluation
and both deposition implementations. Ten focused tests cover Gaussian pulses, pulse
trains, nonuniform temporal/spatial diagnostics, different chunks, host output/cache
ownership, automatic CPU fallback, explicit-CUDA failure, public stage metadata and
retry-safe mass conservation after injected allocation failures.

The 16,384- and 65,536-particle runs compare both backends over
the shared baseline, low-a0 and near-a0-max bank. All checks passed with 64 time steps.
Relative L1 errors for Stage-0 luminosity/effective intensity and Stage-1 density are
around machine precision (below 1e-14); checks require below 1e-10. Source hashes
were unchanged in both runs. Stage-1 comparisons use identical CPU Stage-0 samples to
isolate the deposition operation; engine tests separately exercise the complete GPU path.

## Warm timings

Baseline-case wall time in milliseconds, including host geometry and transfers.
Stage 1 uses a 16×16×16×24 table for both backends:

| Particles | Operation | NumPy ms | CuPy ms |
|---|---|---|---|
| 16,384 | Stage 0 | 445.62 | 13.36 |
| 16,384 | Stage 1 nearest | 0.74 | 2.24 |
| 16,384 | Stage 1 cic | 6.38 | 12.60 |
| 65,536 | Stage 0 | 1498.78 | 62.86 |
| 65,536 | Stage 1 nearest | 5.22 | 5.78 |
| 65,536 | Stage 1 cic | 49.01 | 14.53 |

These are single warm measurements, excluding first-call compilation, not a universal
speedup guarantee. Stage 0 benefits substantially at both sizes. Stage 1 can be slower
for small bunches; CIC benefits at the larger size, while nearest-cell deposition is
similar. Explicit backend selection is respected rather than silently switching the
requested Stage-1 computation back to the CPU based on a size heuristic.

Reproduce on actual CUDA:

```sh
mkdir -p output/validation
PYTHONPATH=src .venv/bin/python scripts/validate_cupy_stages01.py --output output/validation/stages01.json
PYTHONPATH=src .venv/bin/python scripts/validate_cupy_stages01.py --particles 65536 --output output/validation/stages01-large.json
```
